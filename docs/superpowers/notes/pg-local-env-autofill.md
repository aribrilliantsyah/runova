# Env database terisi otomatis

Brief: `.brief-pg-local-env.md`. **Bagian A (PostgreSQL hanya lokal) dibatalkan** oleh revisi user: "untuk database boleh aja kalau mau dibuka, maksudnya yg nanti konek ke aplikasi udah terisi localhost". `listen_addresses`, ufw 5432, `PGAllowedNets`, `WriteHBA`, installer, dan docs akses luar tidak diubah. Yang dikerjakan: Bagian B, plus tambahan opsional petunjuk SSH tunnel di halaman Database.

## Keputusan

1. **Pemetaan di paket sendiri, `internal/dbenv`.** Murni (tanpa store/PostgreSQL), dipakai `dbs.AppEnv` (nilai untuk container) dan `api` (nama + jenis untuk UI), jadi satu sumber kebenaran. `KindOf(name, jar)` → `url|jdbc|r2dbc|host|port|user|password|database` atau `""`. `Vars(detected, jar)` = 9 nama standar (ditandai `standard`) lalu nama terdeteksi yang dikenali, urut, tanpa duplikat. Tabel uji positif/negatif: `internal/dbenv/dbenv_test.go`.
2. **Aturan nama** (huruf besar-kecil sama): nama dipecah di `_`; bentuk lekat `DBURL`, `PGPASS`, `DBNAME` dipecah jadi `DB URL` dst. Kata terakhir = kata field (`URL URI DSN`, akhiran `CONNECTION_STRING`, `HOST HOSTNAME SERVER`, `PORT`, `USER USERNAME LOGIN`, `PASS PASSWORD PWD PASSWD`, `NAME DATABASE DBNAME DB`). Kata-kata sebelumnya harus semuanya kata konteks DB (`DB DATABASE POSTGRES POSTGRESQL PG DATASOURCE JDBC R2DBC TYPEORM SQL`) atau kerangka (`SPRING QUARKUS APP`), dan minimal satu kata konteks DB. Kata lain apa pun (`TEST`, `READ`, `REPLICA`, `ADMIN`, `ROOT`, `SHADOW`, `BILLING`, `REDIS`, `MYSQL`, `MONGO`, `HIKARI`…) = ambigu → tidak diisi. `SQL_SERVER` bukan host (Microsoft). `SCHEMA`, `POOL_SIZE`, `SSL_MODE`, `DRIVER`, `TIMEOUT` bukan kata field → tidak diisi.
3. **Jenis URL:** `R2DBC` di nama → `r2dbc:postgresql://host:port/db`; `JDBC|DATASOURCE|SPRING|QUARKUS` → `jdbc:postgresql://…`; akhiran `DSN` → `postgres://` (DSN libpq/Go); selain itu JAR → JDBC, lainnya `postgres://user:pass@host:port/db` (user/password di-escape oleh `net/url`). Nama standar tetap dengan nilai lamanya (mis. `DATABASE_URL` selalu `postgres://`, juga untuk JAR).
4. **Host = `host.docker.internal`, bukan 127.0.0.1.** Di dalam container `localhost` adalah container itu sendiri; `host.docker.internal` (host-gateway) adalah "server ini (lokal)". UI menulisnya begitu dengan tooltip penjelas.
5. **Sumber nama terdeteksi:** laporan artefak deployment yang di-deploy (`Deployment.Report.Env`, jadi rollback memakai nama versinya) ditambah nama env aplikasi. `.env.example` > properties (`application.properties`/`.yml`/`.yaml`, sudah didukung sebelumnya, termasuk `${DB_URL}` di YAML) > scan.
6. **Override pengguna menang** di `apps.ContainerSpec`: nilai env pengguna yang tidak kosong dipakai; nilai kosong untuk nama yang diisi database diserahkan ke database (rahasia kosong yang dulu terkirim dari wizard tidak menimpa password). Variabel Runova sendiri (`PORT`, `RUNOVA_DATA_DIR`, `HOME`) tetap menang atas semuanya.
7. **API tanpa nilai.** `POST /api/uploads` → `db_env: [{name, kind, standard}]`. `GET /api/apps/{id}` → `db_env: {database, vars: [{name, kind, standard, overridden}]}` atau `null`. `overridden` dihitung di server dari env tersimpan (rahasia didekripsi di server), karena browser hanya menerima rahasia yang dikosongkan. Password tetap hanya lewat jalur "lihat" yang sudah ada.
8. **UI.** Wizard: memilih database mengunci baris yang dikenali jadi "Otomatis · dari `<db>`" (ikon gembok, jenis nilai), tidak wajib, tidak dikirim; "Isi sendiri" membuka field, ikon database mengembalikan ke otomatis. Ringkasan di bawah pilihan database menyebut nama yang terisi + 9 nama standar. Tab Environment: entri yang masih diserahkan ke database tampil terkunci dengan "Isi sendiri" (dialog yang sama; kosong = tetap otomatis); nama terdeteksi tanpa entri juga ditampilkan terkunci; entri yang diisi sendiri diberi chip "isian sendiri" dan tombol ikon database untuk menghapus isian (kembali otomatis). Ganti database tetap di tab Lanjutan, `redeploy_required` seperti sebelumnya.
9. **Rotasi password** tidak berubah: `AppEnv` membaca password tersimpan setiap deploy, jadi semua nama otomatis mendapat password baru setelah deploy ulang (diuji di `TestDetectedDBEnvFilledAutomatically`).
10. **Petunjuk SSH tunnel** (opsional brief, dikerjakan): halaman Database menambah baris salin `ssh -N -L 5433:127.0.0.1:<port> <user-ssh>@<IP publik|domain panel|<host-server>>` dan catatan DBeaver/DataGrip serta `-J` untuk server di belakang NAT/proxy. Detail host publik yang lama tetap ada. Tidak ada kredensial SSH yang disimpan.

## Sengaja tidak dikerjakan

- Semua Bagian A (lihat atas).
- Nama dengan kata kualifikasi bebas (`BILLING_DB_URL`, `DB_PRIMARY_URL`) tidak diisi: tidak bisa dibedakan dari `REPORTING_DB_URL` milik database lain. Pengguna mengisinya sendiri.
- Ikon `undo-2` tidak ada di sprite dan `cmd/genicons` butuh unduhan; tombol kembali-ke-otomatis memakai ikon `database` yang sudah ada.

## Uji

- `go test ./internal/dbenv` (tabel), `./internal/dbs` (`TestAppEnv`: nama terdeteksi, JAR → JDBC, R2DBC), `./internal/apps` (`TestContainerSpec`: pengguna menang, kosong → database), `./internal/api` (`TestDetectedDBEnvFilledAutomatically`: unggah → `db_env`, container env, override, tanpa bocor password, rotasi + deploy ulang, lepas database → `null`).
- `node web/test/smoke-dbenv.mjs` (`RUNOVA_FAKE_BACKENDS=1`): `.tar.gz` dengan `.env.example` `DB_URL= DB_USER= DB_PASSWORD= REDIS_URL=` → pilih database → DB_* terkunci, REDIS_URL tetap wajib, yang dikirim tanpa DB_*; tab Environment terkunci + override; halaman Database menampilkan SSH tunnel. Screenshot ke `RUNOVA_SHOTS` (bawaan `/tmp/runova-pg-env/`).
