# Bagian 2: deviasi dan keputusan

Nama, signature, dan konstanta di blok Interfaces rencana tidak diubah. Hal-hal di bawah adalah koreksi atau tambahan kecil.

1. **Scan env binary dibatasi ke nama yang mungkin konfigurasi.** Rencana: ambil maks 50 string. Binary Go yang memakai `net/http` memuat ratusan konstanta protokol (`AVX512_*`, `HTTP2`, `TLS`), sehingga 50 nama pertama berurutan abjad hanya berisi derau dan nama sungguhan terpotong. Sekarang hingga 4096 kandidat dikumpulkan; bila lebih dari 50, hanya nama yang memuat kata konfigurasi (`PASSWORD`, `SECRET`, `TOKEN`, `KEY`, `URL`, `URI`, `DSN`, `HOST`, `PORT`, `ADDR`, `DATABASE`, `DB_`, `USER`, `ENV`, `MODE`, `LEVEL`) yang dipertahankan, maks 50. Awalan `GLIBC_` ikut diabaikan (versi simbol).
2. **Batas heuristik scan.** Go menaruh string literal berdempetan tanpa pemisah, jadi nama bisa menempel dengan tetangganya (`APP_MODEG`, `SHAKE128JWT_SECRET`, diamati pada binary uji asap). Awalan angka/garis bawah dibuang, tetapi tempelan huruf tidak bisa dipisahkan tanpa mengurai tabel string Go. Hasil scan memang berstatus "kemungkinan" (`Source:"scan"`); `.env.example` tetap sumber utama.
3. **Java > 25.** `MinJava` untuk major di atas 69 diisi `major - 44` (major 70 → 26) bersama masalah "Butuh Java lebih baru dari 25"; rencana hanya menyebut masalahnya.
4. **Masalah tambahan (Bahasa Indonesia):** "JAR tidak berisi kelas Java"; "Bukan binary ELF"; "File ELF tidak valid"; "Binary dinamis dengan interpreter <x> tidak didukung; build statis atau dengan glibc"; "Binary <mesin>, server ini amd64" untuk arsitektur selain ARM64; "Binary bukan untuk Linux" (OS ABI); "File ELF bukan program yang bisa dijalankan" (bukan `ET_EXEC`/`ET_DYN`).
5. **`Inspect` dan arsip ditolak.** `ErrUnsafeArchive`, `ErrTooLarge`, `ErrArchiveContents` (dan `ErrCorruptArchive`, tambahan untuk gzip/tar rusak) dari `ExtractTarGz` diubah `Inspect` menjadi `Report` dengan satu masalah dan path kosong, bukan error; hanya kegagalan I/O yang menjadi error. `workDir` dikosongkan pada kegagalan.
6. **`POST /api/uploads` selalu 201 untuk unggahan yang sempat diperiksa**, termasuk laporan dengan masalah (jenis tak dikenal, arsip tidak aman, runtime dimatikan). Baris `uploads` tetap dibuat agar pengguna bisa membaca laporan dan menghapusnya. Selain itu: 415 bila bukan `multipart/form-data`, 400 bila field `file` tidak ada atau unggahan terputus, 413 "File melebihi batas <N> MB" (juga lewat `Content-Length` sebelum membaca).
7. **Runtime Java dimatikan.** Bila tidak ada versi Java ≥ `MinJava` yang diizinkan admin, masalahnya "Admin menonaktifkan runtime Java <min> atau yang lebih baru di server ini". Untuk binary: "Admin menonaktifkan runtime static|glibc di server ini" (sesuai rencana).
8. **Folder unggahan.** `$RUNOVA_DATA/tmp/<id>/` (0700) berisi `upload` (file mentah; dihapus bila artefak berasal dari `.tar.gz`) dan `files/` (hasil ekstrak). `Upload.ArtifactPath` menunjuk file artefak yang dipertahankan.
9. **Pembersihan.** `CleanupUploads` menghapus folder dulu, baris sesudahnya, supaya kegagalan hapus folder diulang pada putaran berikutnya. Berjalan di `cleanupLoop` yang sudah ada (start dan tiap jam).
10. **Proyek uji asap** disimpan di `testdata/hello-spring/` (Spring Boot 3.5.0, Java 17, tanpa `target/`).
