# Runova Bagian 5: PostgreSQL per Pengguna dan Backup — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Setiap pengguna Runova punya role PostgreSQL, bisa membuat database sampai batas kuotanya, memakainya di aplikasi dengan env terisi otomatis, melihat detail koneksi, dan punya backup harian yang bisa diunduh dan di-restore.

**Architecture:** `internal/pg` membungkus koneksi admin ke PostgreSQL (socket Unix, peer auth sebagai role `runova`) dan semua SQL DDL dengan identifier yang divalidasi lalu di-quote. `internal/dbs` adalah logika domain (kuota, nama, kepemilikan, env aplikasi, backup) di atas interface `pg.Admin`, sehingga sebagian besar diuji dengan admin palsu. Test integrasi memakai PostgreSQL 18 nyata di container Docker (`RUNOVA_PG_TEST=1`). Role pengguna dibuat/diubah/dihapus lewat hook di layanan pengguna, plus rekonsiliasi saat start untuk pengguna yang dibuat sebelum bagian ini.

**Tech Stack:** `github.com/jackc/pgx/v5` (stdlib `database/sql` tidak dipakai di sini), `pg_dump` / `pg_restore` dari paket `postgresql-client-18`.

**Spec:** `docs/spec.md` §3 (kuota database & koneksi), §7, §8, §9.

**Bergantung pada:** Bagian 1 (pengguna, kuota, rahasia), Bagian 3 (`apps.Service.ContainerSpec` menerima `dbEnv`).

## Global Constraints

- DSN admin: `host=/var/run/postgresql user=runova dbname=postgres` (dapat diganti `RUNOVA_PG_DSN`). Gagal konek saat start → peringatan di log dan halaman Server, fitur database menjawab 503 "PostgreSQL tidak bisa diakses", bagian lain Runova tetap jalan.
- Role pengguna = username (sudah sesuai `^[a-z][a-z0-9]{1,30}$`). Atribut: `LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT NOREPLICATION NOBYPASSRLS CONNECTION LIMIT <PGConnections> PASSWORD '<acak 32>'`, lalu `GRANT "<role>" TO runova WITH INHERIT TRUE, SET TRUE`.
- Nama database: `<username>_<nama>`, `<nama>` = `^[a-z][a-z0-9_]{0,30}$`, total ≤ 63 byte. Setelah `CREATE DATABASE "<db>" OWNER "<role>"`: `REVOKE ALL ON DATABASE "<db>" FROM PUBLIC`.
- Semua identifier lewat `pgx.Identifier{…}.Sanitize()` setelah lolos validasi; password lewat literal yang di-escape (`'` → `''`) — DDL tidak menerima parameter bind.
- Env aplikasi dengan database: `DATABASE_URL=postgres://<role>:<pw-url-escaped>@host.docker.internal:5432/<db>`, `SPRING_DATASOURCE_URL=jdbc:postgresql://host.docker.internal:5432/<db>`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD`, `PGHOST=host.docker.internal`, `PGPORT=5432`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`. Env pengguna dengan nama sama ditimpa.
- `pg_hba.d/runova.conf` (path dari `RUNOVA_PG_HBA`, bawaan `/etc/postgresql/18/main/pg_hba.d/runova.conf`): `host all all 172.30.0.0/16 scram-sha-256` + satu baris per jaringan yang diizinkan admin (`Settings.PGAllowedNets []string`, CIDR valid, maks 20), ditulis atomik (tulis file sementara + rename), lalu `SELECT pg_reload_conf()`.
- Backup: `pg_dump -Fc --no-owner -d <db>` ke `$RUNOVA_DATA/backup/<db>/<YYYYMMDD-HHMMSS>.dump` (0600), tiap hari pukul 02:00 waktu lokal server, retensi 7 hari (otomatis), backup manual juga ikut retensi. Restore: `pg_restore --clean --if-exists --no-owner --role=<role> -d <db>`; koneksi lain ke database diputus dulu (`pg_terminate_backend` untuk `datname`).
- Hapus database: `DROP DATABASE "<db>" WITH (FORCE)`, folder backup ikut dihapus. Hapus pengguna: semua database, `DROP ROLE`, folder backup.
- Database yang masih dipakai aplikasi tidak bisa dihapus: 409 "Masih dipakai oleh: billing-api, invoice-pdf".
- Aksi aktivitas: `ActDBCreate = "db.create"`, `ActDBDelete = "db.delete"`, `ActDBBackup = "db.backup"`, `ActDBRestore = "db.restore"`, `ActDBPassword = "db.password"`, `ActDBReveal = "db.reveal"`.

## Review Focus

- **Pengguna A mencoba konek ke database B dengan role A** → ditolak oleh PostgreSQL (`permission denied for database`). Test integrasi di Task 1 (`TestIsolationBetweenRoles`).
- **Pengguna menjalankan `CREATE DATABASE` / `CREATE ROLE` dari aplikasinya untuk melewati kuota** → ditolak PostgreSQL. Test integrasi di Task 1 (`TestRoleCannotEscalate`).
- **Ganti password database saat aplikasi berjalan** → password baru tersimpan, aplikasi yang memakai database itu ditandai `redeploy_required` dan pengguna diberi tahu; role lama tidak ditinggalkan dengan password berbeda dari yang tersimpan bila `ALTER ROLE` gagal (simpan ke DB hanya setelah sukses). Test di Task 3 (`TestRotatePasswordOrder`).
- **PostgreSQL mati** → halaman lain tetap jalan; endpoint database 503; deploy aplikasi yang memakai database tetap jalan (env dari password tersimpan, tidak perlu konek). Test di Task 3 (`TestPGDownDoesNotBreakDeploy`).
- **Restore backup dari database lain milik pengguna yang sama atau milik pengguna lain** → hanya backup milik database itu yang bisa dipilih (ID backup = nama file di folder database itu; path traversal ditolak). Test di Task 4 (`TestBackupPathConfined`).

  - `(*Service).List(ctx, user) ([]DBView, error)` — `DBView{ID int64; Name string; SizeBytes int64; Connections int; Apps []string; CreatedAt int64}` (ukuran/koneksi dari `Databases`, PG mati → 0 dan `PGDown true` di level respons).
  - `(*Service).Delete(ctx, user, dbID, confirm string)` — `confirm` harus sama dengan nama; dipakai aplikasi → `ErrInUse`.
  - `(*Service).Connection(ctx, user, dbID, reveal bool) (ConnInfo, error)` — `ConnInfo{Host string /*Settings.PublicIP atau panel domain*/; Port int; Database, User, Password string}`; `Password` hanya bila `reveal` (dicatat `db.reveal`).

  - `(*Service).AppEnv(ctx, app store.App) ([]string, error)` — nil bila `database_id` NULL; tidak konek ke PG.
  - `(*Service).WriteHBA(ctx) error` — tulis file dari setelan lalu `ReloadConfig`.
  - Error: `ErrQuota`, `ErrInUse`, `ErrPGDown`.

### Task 4: Backup dan restore

**Interfaces:**
- Consumes: Task 2.
- Produces:
  - `type Backup struct{ ID string /*nama file*/; At int64; SizeBytes int64; Manual bool }` (manual ditandai akhiran `-m.dump`).
  - `(*Service).BackupNow(ctx, db store.Database, manual bool) (Backup, error)` — `exec.CommandContext(PGDump, "-Fc", "--no-owner", "-d", db.Name)` ke file sementara lalu rename; gagal → file dihapus.

  - `dbs.NextRun(now time.Time) time.Time` — 02:00 lokal berikutnya (hari ini bila sebelum 02:00).
  - `(*Service).RunSchedule(ctx)` — tidur sampai `NextRun`, backup semua database berurutan, `Prune`; kegagalan per database → notifikasi pemilik "Backup <db> gagal".
