# Runova Bagian 3: Menjalankan Aplikasi di Docker — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dari unggahan (Bagian 2), pengguna membuat aplikasi, mengatur env dan resource, lalu men-deploy, restart, stop, rollback, melihat log live, dan membuka terminal. Crash berulang menghasilkan status Gagal dan notifikasi.

**Architecture:** `internal/docker` adalah klien Engine API minimal di atas `net/http` + socket Unix (tanpa SDK). `internal/apps` memegang logika domain (kuota, port, env, rencana container) dan memanggil `docker` lewat interface `Engine`, sehingga hampir semua logika diuji dengan engine palsu. Test integrasi dengan Docker nyata berjalan bila `RUNOVA_DOCKER_TEST=1`. Bagian ini memakai deploy **stop-start**; mode tanpa jeda datang di Bagian 4 karena butuh Caddy untuk mengalihkan lalu lintas. Sampai Bagian 4, aplikasi bisa dibuka di `127.0.0.1:<host_port>` dari server.

**Tech Stack:** Go stdlib, `github.com/coder/websocket` (log live dan terminal; versi sama dengan proyek tts).

**Spec:** `docs/spec.md` §2, §5, §8, §9.

**Bergantung pada:** Bagian 1, Bagian 2 (`store.Upload`, `artifact.Report`).

## Global Constraints

- Docker Engine API `v1.44` lewat `/var/run/docker.sock` (dapat diganti `RUNOVA_DOCKER_HOST=unix:///path`).
- Image: JAR `eclipse-temurin:<8|11|17|21|25>-jre`; static `gcr.io/distroless/static-debian12`; glibc `ubuntu:26.04`. Image ditarik saat deploy bila belum ada.
- Nama aplikasi: `^[a-z][a-z0-9-]{1,38}[a-z0-9]$`, unik per pengguna. Nama container `runova-<username>-<app>-<deploymentID>`; label `runova.user`, `runova.app`, `runova.deployment`.
- Container: `User: "<100000+userID>:<100000+userID>"`, `ReadonlyRootfs`, tmpfs `/tmp` (64 MB), `CapDrop: ["ALL"]`, `SecurityOpt: ["no-new-privileges"]`, `Memory` = MB×1048576, `MemorySwap` = sama dengan `Memory`, `NanoCPUs` = millicore×1e6, `PidsLimit: 512`, `RestartPolicy: on-failure`, `LogConfig json-file max-size=10m max-file=3`, `ExtraHosts: ["host.docker.internal:host-gateway"]`, jaringan `runova-u<userID>`, port internal → `127.0.0.1:<host_port>`.
- Mount: artefak read-only ke `/app/<nama file>`; folder data `$RUNOVA_DATA/data/<username>/<app>` ke `/data` (dibuat dengan owner UID pengguna, mode 0700).
- Perintah: JAR `java <jvm_opts> -jar /app/<file>`; binary `/app/<file>` (bit eksekusi dipasang saat disimpan).
- Env selalu diisi Runova (menimpa env pengguna): `PORT`, `RUNOVA_DATA_DIR=/data`, `HOME=/tmp`.
- Alokasi resource per aplikasi: memori 128–kuota MB kelipatan 64; CPU 100–kuota millicore kelipatan 50.
- Host port acak dari 30000–39999 per **deployment** (`deployments.host_port`; unik di antara deployment yang belum `superseded`/`failed`, dicek bebas dengan `net.Listen`), supaya Bagian 4 bisa menjalankan container lama dan baru bersamaan; port akses IP dari `Settings.PortMin..PortMax`, dialokasikan saat aplikasi dibuat, tetap seumur aplikasi.
- Sehat = TCP connect ke `127.0.0.1:<host_port>` berhasil dalam 60 detik.
- 10 deployment terakhir per aplikasi disimpan (artefak + snapshot env terenkripsi); yang lebih lama dihapus beserta file.
- Crash: > 5 kali `die` dalam 10 menit → status `failed`, container dihentikan, notifikasi.
- Terminal: hanya `jar` dan `glibc`; `docker exec` `/bin/sh` sebagai UID pengguna, TTY; WebSocket ditutup setelah 30 menit idle.

## Review Focus

- **Deploy gagal sehat (port salah, aplikasi langsung exit)** → status `failed`, deployment lama tetap tercatat, log 200 baris terakhir container yang gagal disimpan di deployment, container gagal dihapus. Test di Task 4 (`TestDeployUnhealthy`).
- **Dua deploy bersamaan untuk aplikasi yang sama** → yang kedua 409 "Deploy sedang berjalan". Test di Task 4 (`TestDeployConcurrent`).
- **Pengguna B memakai ID aplikasi/deployment/terminal milik A** → 404 di semua endpoint, termasuk WebSocket. Test di Task 5 (`TestAppOwnership`).
- **Runova restart saat aplikasi berjalan** → container tetap jalan, status disinkronkan dari Docker saat start, tidak ada deploy ulang. Test di Task 6 (`TestReconcileOnStart`).
- **Kuota diturunkan admin di bawah pemakaian** → aplikasi berjalan tidak disentuh; mengubah resource/membuat aplikasi baru ditolak dengan pesan berisi sisa kuota. Test di Task 3 (`TestQuotaBelowUsage`).
