# Runova Bagian 1: Fondasi — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Binary `runova` yang bisa `serve` API JSON dengan login, manajemen pengguna dan kuota oleh admin, setelan server, log aktivitas, serta perintah `runova admin create`.

**Architecture:** Satu modul Go `runova`. `internal/config` membaca env; `internal/secret` mengenkripsi nilai rahasia; `internal/store` memegang SQLite (modernc, tanpa cgo); `internal/auth` mengurus password, sesi cookie, dan batas percobaan login; `internal/api` adalah handler HTTP JSON di atas store dan auth; `cmd/runova` merangkai semuanya. Pola mengikuti `~/Documents/Repos/Go/tts` (store dengan schema `CREATE TABLE IF NOT EXISTS` di DSN-pragma, `auth.Sessions.Require`, helper `writeJSON`/`writeError`/`decode`).

**Tech Stack:** Go 1.27, `modernc.org/sqlite`, `golang.org/x/crypto/bcrypt`, `net/http` (ServeMux pola metode+path), `crypto/aes`+`cipher.NewGCM`.

**Spec:** `docs/spec.md` (bagian 2, 3, 8, 9 untuk rencana ini).

## Global Constraints

- Modul: `module runova`, `go 1.27`. Tanpa cgo (`CGO_ENABLED=0 go build ./...` harus lulus).
- Dependensi hanya `modernc.org/sqlite` dan `golang.org/x/crypto`. Tanpa framework HTTP/router.
- Pesan error untuk pengguna dalam Bahasa Indonesia; log (`log/slog`) dalam bahasa Inggris.
- Waktu disimpan sebagai Unix milidetik (`INTEGER`); semua kode yang bergantung waktu menerima `Now func() time.Time`.
- Username: `^[a-z][a-z0-9]{1,30}$`; dicadangkan: `postgres`, `runova`, `root`, `public`, `template`.
- Password: 10–200 karakter (dihitung rune).
- Cookie: `runova_session`, `HttpOnly`, `SameSite=Lax`, `Secure` bila `r.TLS != nil` atau `X-Forwarded-Proto: https` dari loopback; masa berlaku 7 hari; token disimpan sebagai hex SHA-256.
- Batas login: 5 gagal / 15 menit per (username, IP) → kunci 15 menit.
- Kuota bawaan: aplikasi 3, memori 1024 MB, CPU 1000 millicore, database 3, koneksi PG 20.
- Setelan bawaan: unggahan 500 MB, port 20000–20999, runtime `java8,java11,java17,java21,java25,static,glibc` semua aktif, IP publik kosong.
- Env: `RUNOVA_LISTEN` (`127.0.0.1:7070`), `RUNOVA_DATA` (`/var/lib/runova`), `RUNOVA_SECRET_KEY` (`/etc/runova/secret.key`). DB di `$RUNOVA_DATA/runova.db`.
- Badan JSON maks 1 MiB. Mutasi wajib `Content-Type: application/json`; `Origin` bila ada harus sama dengan `Host`.

## Review Focus

- **Admin terakhir menurunkan/menghapus dirinya** → ditolak 409 "Minimal harus ada satu admin". Test di Task 5 (`TestLastAdminProtected`).
- **Username beda kapitalisasi (`Budi` vs `budi`)** → ditolak validasi (huruf kecil saja), bukan jadi akun kedua. Test di Task 2 (`TestValidateUsername`).
- **Brute force dari banyak IP lewat Caddy** → IP diambil dari `X-Forwarded-For` hanya jika `RemoteAddr` loopback; klien luar yang memalsukan header tetap dihitung per IP aslinya. Test di Task 4 (`TestClientIP`).
- **Pengguna dihapus saat sesinya masih aktif** → permintaan berikut 401, bukan 500. Test di Task 5 (`TestDeletedUserSessionRejected`).
- **File kunci rahasia hilang/berukuran salah** → `serve` gagal start dengan pesan jelas, bukan membuat kunci baru diam-diam (yang akan membuat semua rahasia lama tak terbaca). Test di Task 1 (`TestLoadKeyErrors`).

**Files:**
- Create: `internal/api/api.go` (router, helper JSON, origin check), `internal/api/session.go`, `internal/api/users.go`, `internal/api/settings.go`, `internal/api/activity.go`, `internal/api/api_test.go`

**Interfaces:**
- Consumes: Task 2–4.
- Produces: `api.New(api.Config{Store *store.Store; Now func() time.Time}) http.Handler`.

Endpoint (semua di bawah `/api`, respons JSON; error `{"error":"<pesan>"}`):

| Metode & path | Akses | Isi / hasil |
|---|---|---|
| `POST /api/login` | publik | `{username,password}` → 200 `User`; salah → 401 "Username atau password salah"; terkunci → 429 "Terlalu banyak percobaan. Coba lagi pukul HH:MM" (+ header `Retry-After` detik) |
| `POST /api/logout` | login | 200 `{"ok":true}` |
| `GET /api/me` | login | `User` |
| `POST /api/me/password` | login | `{current,new}`; current salah → 400; sukses → sesi lain terhapus, sesi baru dibuat untuk permintaan ini |
| `GET /api/users` | admin | `[]User` |
| `POST /api/users` | admin | `{username,display_name,email,password,role}`; kuota = `Settings.DefaultQuota`; → 201 `User`; duplikat 409 "Username sudah dipakai" |
| `PATCH /api/users/{id}` | admin | `{display_name?,email?,role?,quota?}` → `User`; admin terakhir → 409 "Minimal harus ada satu admin" |
| `POST /api/users/{id}/password` | admin | `{password}` reset password pengguna |
| `DELETE /api/users/{id}` | admin | hapus diri sendiri → 409 "Tidak bisa menghapus akun sendiri"; admin terakhir → 409 |
| `GET /api/settings` / `PUT /api/settings` | admin | `Settings` |
| `GET /api/activity?before=&limit=` | login | pengguna biasa: hanya miliknya; admin: semua, opsional `?actor=<id>` |

Setiap mutasi menulis `Activity` dengan aksi dari Task 3 (login gagal dicatat dengan `ActorName` = username yang dicoba). Middleware mutasi (`POST/PATCH/PUT/DELETE`): bila `Origin` ada dan host-nya ≠ `r.Host` → 403 "Origin tidak diizinkan". Body maks 1 MiB, Content-Type wajib JSON (415).
